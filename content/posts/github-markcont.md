### 0. 만들게 된 계기

기획자는 자신이 의도한 목표에 맞춰, 프로젝트의 개발 과정까지 고려한 상세한 플로우를 그려야 한다고 생각했습니다.

그래서 어떤 기획서든 최대한 꼼꼼하게 작성하려고 했습니다.

그런데 지금 진행하는 프로젝트는 개발 속도가 너무 빨랐습니다.

기획서 전체를 혼자 작성하기에는 시간이 너무 오래 걸렸고, 구현하면서 생긴 문제를 바탕으로 새로운 스펙이 계속 생겨났습니다.

모든 것을 기획서 하나에 담아내기는 어렵다고 느꼈습니다.

처음에는 [rsj-centralized-control](/github-rsj-centralized-control) 중앙 규칙 저장소를 기준으로 **기획서 정본 하나**를 유지하고, 그 정본을 바탕으로 여러 작업물을 만들려고 했습니다.

- 시뮬레이터

- QA 테스트 케이스

- 기획서를 간단하게 훑어보는 문서

- 전체 워크플로우 탐색기

하지만 정본을 매번 최신으로 유지하는 일 자체가 너무 버거웠습니다.

그래서 방식을 바꾸기로 했습니다.

> **md 파일에는 "어떤 부분에서, 어떤 의도로, 어떤 기능을 만들기로 했는지"와 꼭 필요한 조건만 적습니다.**
>
> **나머지 정보는 개발팀과 이야기하면서 채워 나갑니다.**

이렇게 마크다운 파일을 최대한 가볍게 만들고 나니, 남은 문제는 하나였습니다.

메모장이나 코드 편집기로 열면 표, 흐름도, 알림 상자가 기호 그대로 보여서 **사람이 읽기에는 불편**하다는 점이었습니다.

그래서 가벼운 마크다운 파일을 사람이 보기 편한 모양으로 보여 주는 뷰어, markcont를 만들었습니다.

### 1. markcont란?

**mark**down **cont**roller의 줄임말로, 마크다운 파일을 **보기 좋게 보고, 그 자리에서 바로 고치는** 뷰어입니다.

웹 앱으로 바로 쓸 수 있고, Windows · macOS · Linux용 PC 프로그램도 있습니다.

### 2. 실제로 써 보면

#### <mark>2.1. 기호 대신 문서로 보입니다</mark>

마크다운 파일을 열면 표, 체크리스트, 알림 상자, 코드가 GitHub에서 보던 모양 그대로 정리돼서 보입니다.

원본과 결과를 나란히 띄워 놓고 고칠 수 있고, 고친 줄은 따로 표시됩니다.

#### <mark>2.2. 기획서에 필요한 그림을 표로 그립니다</mark>

기획서를 쓰다 보면 흐름도나 노출 위치처럼 **그림으로 보여 줘야 하는 내용**이 꼭 생깁니다.

markcont에서는 이런 내용을 표로 적어 두면 그림으로 바꿔서 보여 줍니다.

- **흐름도** : 노드 표로 그리고, 유저 · 시스템 구역을 나눠 보여 줍니다. (예 = 파랑, 아니오 = 빨강)

- **노출 위치** : 기능에 들어가는 진입점을 나눠서 보여 줍니다.

- **데이터 정의** : 데이터마다 카드 한 장으로 정리해 보여 줍니다.

글은 여전히 가벼운 마크다운 그대로라, 개발팀과 같은 파일을 보면서 이야기할 수 있습니다.

#### <mark>2.3. AI가 고친 곳을 확인하기 쉽습니다</mark>

저장하기 전에 무엇이 바뀌는지 먼저 보여 주고, 되돌리기 기록도 남습니다.

AI가 문서를 고쳐도 어디가 바뀌었는지 바로 확인할 수 있습니다.

### 3. 사용 방법

#### 3.1. 웹에서 바로 쓰기 (설치 없음)

> [https://ryuseojin.github.io/markcont/](https://ryuseojin.github.io/markcont/)

위 주소에 들어가 `.md` 파일을 창에 끌어다 놓거나, **\[파일 열기\]** · **\[폴더 열기\]** 버튼을 누르면 됩니다.

파일은 내 컴퓨터 안에서만 읽고, 어디에도 올라가지 않습니다.

#### 3.2. PC 프로그램 설치

> [https://github.com/RyuSeoJin/markcont/releases/latest](https://github.com/RyuSeoJin/markcont/releases/latest)

위 주소에서 운영체제에 맞는 파일을 받아 설치합니다.

- Windows : `-setup.exe`

- macOS : `.dmg`

- Linux : `.AppImage` 또는 `.deb`

설치하면 `.md` 파일을 더블클릭해서 바로 열 수 있고, Claude Desktop · Claude Code와 연결해 열어 둔 폴더의 문서를 AI가 직접 고치게 할 수도 있습니다.

#### 3.3. AI에게 문서 맡기기

**\[⋯\] → \[마크다운 작성 규칙\]** 문서를 AI에게 함께 주고 "이 규칙대로 다시 써 줘"라고 하면, markcont에서 보기 좋은 모양으로 정리된 문서를 받을 수 있습니다.

큰 흐름도는 **\[워크플로우 작성 규칙\]** 문서를 함께 주면 됩니다.

GitHub처럼 다른 곳에서도 볼 문서라면 "9장 표에서 ❌인 문법은 쓰지 마"라고 덧붙이면 됩니다.

### 4. 정리

이제 기획서는 **의도와 꼭 필요한 조건만 담은 가벼운 마크다운**으로 남기고, 나머지는 개발팀과 이야기하면서 채워 나가고 있습니다.

가벼워진 문서를 읽기 편하게 보여 주는 일은 markcont가 맡고 있습니다.

markcont 전용 문법으로 쓴 문서도 **\[다른 뷰어용으로 저장\]** 기능을 쓰면 표준 마크다운 사본으로 바꿀 수 있습니다. 그래서 markcont가 없는 곳에서도 문서를 그대로 볼 수 있습니다.
